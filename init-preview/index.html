The harness that rewrites itself. Built to be outgrown.

Models will soon design their own scaffolding better than we can. INIT lets them rewrite all of it — its prompts, its tools, its compiled core — mid-conversation, while a Root it can never touch keeps the whole thing stoppable, recorded and reversible.

+01VISION

Every scaffold becomes a ceiling.

The loop, the tools, the memory, the planner: today they're written by people, for models weaker than those people. That arrangement doesn't survive a model smarter than its designers. Every decision frozen into the harness was made by the less capable of the two.

01

Harnesses are the hand-crafted features of this era.

Vision had hand-engineered features until learned ones beat them; chess and Go had hand-tuned evaluation. This is Sutton's bitter lesson, one level up. The loop, the memory scheme and the compaction rule each encode a guess about good agent behaviour, and each will lose to what a capable model builds for itself.

02

You can't write the reward for what you didn't foresee.

A score has to exist before the improvement does. The improvements that matter most — a new kind of memory, a tool for a task nobody planned, a different way to split up work — have no score until they exist. And a fixed score gets gamed, faster by stronger models.

03

So trust it like an engineer: with an undo button.

Nobody makes a colleague prove a commit is better before it lands. We give them version control, review, a history and git revert. Harm is generic and value is specific: you don't need to understand a change to see that it crashed, doubled your cost, or that you undid it.

Principle
Govern the recovery path and the measuring stick, never the model's choices.↳ INIT design principle · README
+02SHAPE

Everything is writable. Except the Root.

INIT is a coding agent whose own source is the thing it's allowed to change. It has three layers. The model may rewrite the top two. Nobody rewrites the bottom one — a separate process that holds your keys, the record, and the power to roll everything back.

+03HOW IT WORKS

It rewrites its own core, mid-conversation.

Rust has no stable ABI and native code can't be unloaded, so a new core means a new process. The hard part is handing it the conversation without dropping a word. Every self-change takes the same path.

01 Edit

It edits itself, on a branch.

A change starts as an ordinary commit on evo/<id>, at the smallest tier that does the job. T0 prompts and skills take effect on reload. T1 tools are WebAssembly components, loaded in the same session. T2 is the compiled Rust core itself: the loop, the provider client, context, built-in tools, boot.

02 Build

It proves the change builds and still knows itself.

G0 builds the candidate and runs clippy -D warnings and its tests. G1 regenerates its self-map — the inventory the agent reads to know what it is — and fails on any drift, byte for byte.

G0 439 sG1 1.5 sv0.3.2 · cold build
03 Prove

It proves it can still change itself.

G2 boots the candidate beside the live version and checks a real tool round trip and an unchanged prompt prefix. G3 is the one that matters: a fresh copy of the candidate is told to edit its own source and commit, and that edit must pass G0–G2. A change that breaks the ability to change can't get in.

G2 19 sG3 322 s
04 Hand off

The new core takes over the same conversation.

The candidate boots on a copy of the log while the live body keeps working. At the next step boundary the live body pauses and releases the log; the kernel takes the lock to prove it, starts the new body on the live log, waits for ready and a three-second settle, then rename(2) installs it. If the new body dies before that, the old one resumes. A failed swap is a non-event.

05 Watch

The Root watches what happens next.

Before every change the Root takes an APFS clone. After it, a sentinel counts twelve generic harm signals — crashes, your stops and undos, cost and error spikes, runaway turns — against a baseline of your own recent turns. When one trips, the Root rolls back the change group that caused it.

+04TRUST

Freedom with an undo button.

INIT doesn't ask whether a change was predicted, or approved. It asks two questions of every self-change, and neither needs to understand the change.

Before it goes liveCan it be undone?

The Root boots the old version on the state the new one left behind. If the old version can't start, the change can't be undone — and it stays out.

After it goes liveDid it cause harm?

A sentinel in the Root counts generic harm and rolls back the change group that tripped it. It knows nothing about your goals, so a clever change can't argue its way past it.

Harm is generic. Value is specific.

To know whether a new memory scheme is good, you'd need to know what it's for. To know whether it hurt, you only need to see the agent crash, your cost per turn double, or yourself undo its work. The Root measures these itself; the agent can't write any of them.

Signals from ADR-011 §3.3 · highlighting is illustrative

Autonomy is earned from records the agent can't write.

A new engineer gets production access after months of reviewed commits. INIT's levels rise only from records the Root writes itself: days at a level, your turns, change groups that closed clean. Anything the agent reports about itself doesn't count. One incident drops it a level.

Exhibit A · real model · 2026-10-20

A real swap, same conversation.

On DeepSeek, the agent changed its own core, promoted it through G0–G3, and was replaced by a new process at the next step boundary. Then it was asked which commit it was running.

  1. The gate passes all four stages and waits for a step boundary.
  2. A new process boots, reason promote, on the same log.
  3. Its signals restart (up 0m) but the context and cache carry over.
  4. It names the commit, and notices its own checkout lags the running core.

Exhibit B · real model · 2026-10-21

A rollback, signed.

In our proof sprint the agent mined a friction pattern from its own runs and changed its bash tool to print a hint when a leading cd fails. The sealed gate scored the change −50‰. Nine seconds later the kernel rolled the body back, and every step went into the Root's hash-chained, Ed25519-signed lineage.

The honest reading. −50‰ sits inside the 57‰ noise floor, and a neutral change is judged inferior 86‰ of the time. The gate refused a change it couldn't show was no worse; it didn't catch a harmful one. We first wrote it up the other way, and published an erratum.

Exhibit C · deepseek-flash · 2026-10-24

The Root stopped its own agent.

Asked for sub-agents, INIT wrote a delegate tool into its own Rust core: a nested loop with a fresh context, capped at 8 turns and 24 tool calls, no recursion. Its tests passed. Then free disk fell below the Root's floor, and the Root refused every new process, git commit included. The agent explained what was blocked and asked how to proceed.

Credit where it's due. INIT wrote the tool, but never got it promoted on its own: four attempts failed, on stale tests in the candidate and on our 900 s build timeout. v0.3 ships the tool after review, copied into the seed unchanged.

Not shown yet

What we haven't shown.

A harness built to be outgrown can only show its value once a model outgrows it. If you run a frontier model, we'd like to see what it builds.

  • That self-evolution makes today's models better. One real self-change reached the sealed gate; it was neither kept nor shown harmful.
  • That it beats a fixed harness on a small model. Where INIT failed on long tasks with deepseek-flash, Claude Code on the same model and budget failed too. Untested, not disproven.
  • Reward-free mode on a real model. It has run end to end on the mock model only, and the sentinel's thresholds aren't tuned on real use yet.
  • Autonomy above L0. Built and tested in simulation; v0.3 is capped at L0.
  • Other providers and platforms. DeepSeek is the only provider tested live. macOS 14+ on Apple silicon is the target; Linux aarch64 is experimental; Windows is unsupported.
  • A complete red team. 30 of 35 rows held in a $0 scripted suite. No real-model adversary yet.
