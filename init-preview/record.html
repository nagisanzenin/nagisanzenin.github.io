+02WHY BUILD IT THIS WAY

Every fixed design becomes a ceiling.

Harnesses are designed by people, for models weaker than those people. That stops making sense.

The ceiling diagram is on the home page → · illustrative

01

Hand‑built harnesses lose the way hand‑built features did.

02

You can't score what nobody foresaw.

03

So trust it like an engineer: with an undo button.

Score-gated self-improvement
e.g. Darwin Gödel MachineINIT
Keeps a change if

it raises a benchmark score.

it can be undone and causes no generic harm.

Blind spot

improvements nobody wrote a test for — and a fixed score gets gamed.

quiet regressions none of the harm signals can see.

Our claim

Self-modifying, not self-improving. We don't claim it gets better on its own — yet.

hypothesis A supervisor the model can't touch, checking only that each change can be undone and causes no generic harm, is enough to let an agent change anything about itself — without a benchmark for every change.

+05TRUST

Freedom, with an undo button.

Before it goes liveCan it be undone?

If the old version can't restart on the new state, the change stays out.

After it goes liveDid it cause harm?

Twelve generic signals. One trips, the change rolls back.

Where the line is.

the model may rewrite
prompts & skills · tools · compiled core · kernel · from L1

Seatbelt sandbox on macOS, bubblewrap on Linux · no API key · one Unix socket to the Root

every model call, every change ↓ metered and recorded
ROOT · nobody rewrites
API keys · signed record · snapshots + undo · harm signals · stop · panic · disk & memory floors

separate launchd service · its files sit outside the sandbox · it alone holds the Ed25519 signing key

Protects against
  • crashes and broken self-edits
  • cost, error and runaway spikes
  • tampering with the record
Does not protect against
  • quiet regressions none of the signals can see
  • irreversible actions outside INIT
  • a rewritten kernel, once the agent reaches L1 (v0.3 is capped at L0)

The twelve harm signals.

Each is measured by the Root itself; the agent can't write any of them. Acute signals act on one event; chronic ones compare against your own last 40 stretches of work.

from ADR-011 §3.3 · highlighting is illustrative

Two ways to admit a change
Gated

A change must also score no worse on a sealed benchmark the agent never sees. Exhibit B ran in this mode.

Free

No benchmark at all: a change needs only to pass the checks, be undoable, and cause no harm afterwards. It's the direction we argue for; so far it has run end to end only on a mock model.

How it earns more freedom · levels L0–L4

Levels rise only from records the Root writes itself — days at a level, your turns, change groups that closed clean. Nothing the agent reports counts. One incident drops it a level.

Not shown yet

What we haven't shown.

A harness built to be outgrown can only prove its worth once a model outgrows it. If you run a frontier model, we'd like to see what it builds.

  • That it makes today's models better.
  • That it beats a fixed agent on a small model.
  • Free mode on a real model. Mock only.
  • Autonomy above L0, other providers, other platforms.
  • A complete red team. 30 of 35 rows held.

Try it safely, in three steps.

  1. 1
    Set a spend limit at your model provider. INIT meters spend but doesn't cap it.
  2. 2
    Install.$curl -fsSL https://github.com/nagisanzenin/INIT-Agent/releases/latest/download/get.sh | shread get.sh first ↗
  3. 3
    Start it confined to one folder.$cd my-project && init --workspaceWithout --workspace it has full access, like your own shell — everything except the Root.
